## 3. ★ Deployment reality (folded-in insight, high-value) — authored ≠ applied; AWS is empty

The last snapshot's "deploy unbuilt" upgraded to **"deploy authored but not applied."** That is real progress, but it is *not* "deployed." Concretely:

| Piece | IaC / artifact | Deployed? | Where it would go |
|---|---|---|---|
| Agent suite (runner/planner/gateway/sites) | `Dockerfile` + compose — **no AWS IaC** | ❌ **image never pushed to a registry** | always-on host (Fly/Railway/ECS/VM) |
| central-kg-api | `Dockerfile` (Lambda/Mangum) + `Dockerfile.server` | ❌ | Lambda **or** container `:8000` |
| Avatar | ✅ full Terraform (`avatar-agent/deploy/terraform/`) | ❌ **no `*.tfstate` anywhere → never `apply`'d** | AWS (EC2 LiveKit + ECS + ECR + S3/CF + dispatch Lambda) |
| Data (PG+pgvector, OpenSearch, Kafka) | `infra/provision.sh` | ✅ **live & running** | **Aiven on DigitalOcean (`do-lon`)** — *not AWS* |

**The honest read for "is it easy to deploy exactly what we need and link it up?":**
- The architecture is genuinely **env-flip deployable** — no code change to move from redpanda→Aiven Kafka or local→cloud (`KAFKA_*`, `DATABASE_URL`, `GATEWAY_URL`, `KG_API_URL`, `NEXT_PUBLIC_GATEWAY_WS_URL`). That design pays off here.
- **But there is unbuilt work between "authored" and "a judge can click it":** push the agent-suite image (never done), stand up one always-on host, and put **public `wss://` TLS** in front of the gateway (the browser opens the socket *directly*) and the sites host (or artifact links 404). [DEPLOY.md §5](../docs/DEPLOY.md) names both traps.
- **AWS specifically is the *harder* path and isn't what the runbook recommends.** [DEPLOY.md §6](../docs/DEPLOY.md) recommends **Vercel + Fly/Railway + Lambda**, precisely because ECS/Fargate + ALB + ACM + VPC is heavier than a 4-minute demo needs. Aiven's free tier isn't even on AWS. Lowest-effort AWS option = a **single EC2 box running `docker compose` + Caddy** (no new IaC, a few hours). The avatar's AWS Terraform is the heaviest and least-tested (never applied).
- **Recommendation stands:** deploy the *clickable loop* (FE→Vercel, suite→one Fly/Railway app, KG→Lambda/same host, Aiven already up) and **keep the avatar local**, narrating over the cloud loop from a laptop. Don't spend the last day fighting ECS.

## 10. How the project is progressing (and what to guard against)

Between the two snapshots the team did the rarest thing in a hackathon: **it closed its own review's roadmap.** The delegate seam, the planner, Path-C retrieval, the container, the gateway hardening, the real web-agent, the merged avatar — all the wires the last pass called "the remaining risk" now exist and the loop ran end-to-end in Docker. On top of that the FE quietly became a genuine strength. The engineering quality and the honesty of the doc system remain the project's signature.

The risk has **moved, not grown**: from "do the parts connect" (they do) to **"is it authenticated and reachable"** — a lapsed token and an undeployed (and AWS-empty) stack. Both are operational and bounded.

**Guard against:** (1) burning the last day on a *hard* deploy target (AWS/ECS) when the runbook's easy path (Vercel + Fly + local avatar) wins the same points — or worse, deploying nothing because the hard path stalled; (2) leaving a large amount of *verified, judge-facing* work uncommitted in a dirty tree; (3) walking on stage with the MCP read still red because the token wasn't refreshed; (4) letting the pitch claim "deployed on AWS / pgvector semantic search" when the truth is "containerized, runs on one host, BM25+graph retrieval" — the honest version is still a strong story and survives a judge's question. The marginal **re-auth**, the marginal **commit**, and the marginal **easy deploy** are each worth more right now than any new feature.
