## 3. ★ The retrieval-stack reality (new, high-value) — three paths, and the good one isn't wired

There are **three** retrieval mechanisms in the repo, and they are not the same path:

| Path | Mechanism | Who uses it | Quality | Status |
|---|---|---|---|---|
| **A. Live API `/query`** | `pg_trgm` name match + unindexed `properties ILIKE` | **avatar `lookup_context`**, FE graph search | **Weak** for natural language (trigram ≈ fuzzy *string* match, not meaning/relevance) | live |
| **B. git-agent via MCP** | LLM writes SQL → `aiven_pg_read` recursive CTE | git-agent (the 34% proof) | **Good for structured** ("who touched X"); depends on the LLM writing correct SQL | live (gated by §0 toggle) |
| **C. Bench** | OpenSearch **BM25** → top-K → 2-hop CTE | **nobody in the product** — only `bench/retrieval.py` | **Best** (real full-text relevance + graph expansion); ~125 ms measured | bench-only |

**The problem:** the demo's *conversational* retrieval (the avatar answering "what's blocking the memory refactor?")
runs on **Path A (trigram)** — the weakest — while the **best path (C, BM25+graph) exists only in a benchmark script no
agent calls.** pgvector (the thing the docs repeatedly cite as the semantic spine) is **Path-zero**: every embedding is
`NULL`.

**This is the highest-leverage *quality* opportunity in the project**, and it cuts three ways:
- **Pitch honesty (Anthropic written submission):** stop describing "pgvector semantic search" as live. Either wire an
  embeddings provider (Voyage AI — Anthropic's partner; the stub file already names it) **and re-seed**, or reframe the
  retrieval story around **BM25 + recursive-CTE graph expansion**, which genuinely works and is fast.
- **Demo quality:** route the avatar's `lookup_context` (or a new worker) through **Path C** — the BM25→CTE that the
  bench already proves — instead of trigram. Retrieval goes from "fuzzy string match" to "actually finds the right
  context." Medium effort, large visible payoff.
- **Rubric:** Path C through MCP (`aiven_pg_read` for the CTE half; OpenSearch half is HTTP since Aiven MCP has no
  verified OpenSearch tool) is *more* MCP-native than the trigram API hop. It also retires the "pgvector is fiction"
  exposure.

## 5. Code-quality & correctness findings (actionable, with refs)

**agent-system**
- **WS feed will silently drop fast results.** `gateway.py:73` opens a *fresh consumer group per connection* with
  `auto_offset_reset="latest"`. `POST /tasks` is fire-and-forget; a fast task (echo/git) can complete before the new
  group finishes join + partition assignment, so the result is produced past an offset the consumer never reads → the
  dashboard shows nothing. **Demo-day flake.** Fix: one shared gateway consumer + an in-memory ring buffer replayed on
  WS connect (also kills consumer-group-per-tab sprawl from the auto-reconnect loop).
- **One bad message kills the whole feed.** `gateway.py:81` validates inside the `async for`; an unknown/malformed
  message throws → the `except` tears down the socket for *all* later messages. Make it skip-and-continue per message.
- **Three sources of truth for intents** — `TaskIntent` literal (`contracts.py:48`), `TASK_TOPIC_BY_INTENT`
  (`config.py:37`), `REGISTRY` (`registry.py:9`). Consistent today; will drift on the next intent. Collapse to one
  declarative `intent → (topic, handler)` table.
- **In-memory dedupe** (`harness.py:_seen`) is unbounded + per-process. Fine for one container/demo; note it.
- `git.py` uses `model_fast` (Haiku) to author recursive-CTE SQL — see §6.

**central-kg-api**
- **SQL-injection smell** (low risk today): `entity.py:50` / `timeline.py:36` build WHERE via f-string join. Clauses are
  hard-coded → safe now, but one careless future clause opens it. Parameterize the assembly.
- **Unindexed property scan**: `graph.py:241` `properties::text ILIKE` is a full scan; add a GIN index if the graph
  grows, or drop it from the fallback.
- **Open CORS + no auth** (documented as TODO). Add a shared bearer before any public demo URL.

**meet-joiner**
- Loose client typing: node id `string` vs DB `UUID`; `TaskResultPayload` cast without runtime validation
  (`dashboard/page.tsx`). Works on the wire; fragile. A tiny zod guard on inbound WS envelopes would harden the feed.
- Graph "expand neighbors" swallows errors silently (no pending/failed signal).
- WS backoff has no jitter (thundering-herd if many tabs reconnect together) — minor at demo scale.

**Verified OK (so you don't re-check):** anthropic `0.112.0`; `anthropic.lib.tools.mcp.async_mcp_tool` and
`beta.messages.tool_runner` both exist and are used correctly (both **beta** — keep the version pinned via `uv.lock`,
don't bump before the pitch). Kafka SASL_SSL/mTLS handling in `shared/kafka.py` is correct for Aiven. FE intent vocab,
topic mapping, artifact enum, and result-payload shape all match `contracts.py`. Envelope `schema_`→`schema` alias
serializes correctly on the wire.

## 6. Review of the two proposed changes (deeper)

**(A) Template the git-agent SQL for the headline intents.** Still recommended, now *with* the `ask.py` evidence that
Haiku can write working SQL. Refined position:
- Keep the LLM path for open-ended `read_git` questions, but add **parameterized SQL** for `who_changed` /
  `recent_changes` (the demo intents). Benefits stack: **faster** (no LLM round-trip on the hot path — exactly the
  §3.5 "programmatic MCP" idea the docs already endorse), **more reliable** (no live CTE authoring), and **still via
  MCP** (it's still an `aiven_pg_read`). The LLM then only *phrases* the rows (one cheap Haiku call) or is skipped.
- Risk it removes: a malformed CTE on stage. Risk it adds: the templated SQL must match the seeded schema
  (`person -AUTHORED-> commit -TOUCHES-> file`) — write it against the *actual* seeded graph, not the doc schema.
- **Verdict:** do it for `who_changed`/`recent_changes` before the demo. ~30–40 lines. High ROI.

**(B) Fix the gateway WS (shared consumer + replay buffer + per-message resilience).** Confirmed necessary (§5). Refined
design:
- One module-level consumer task started in `lifespan`, fanning out to a set of connected `WebSocket`s, backed by a
  bounded `deque` (e.g. last 200 envelopes). On connect: replay the buffer (optionally filtered by `meeting_id`), then
  stream live. Per-message `try/except` so one bad frame can't kill a socket.
- This removes three problems at once: the missed-fast-result race, the consumer-group-per-tab sprawl, and the
  one-bad-message teardown. It also makes the dashboard deterministic for a recorded demo (you can open the page *after*
  asking and still see the result). ~60–80 lines, contained to `gateway.py`.
- **Verdict:** do it. It's the difference between "click ask, watch it work" and "click ask, sometimes nothing appears."

Both changes are inside `agent-system` (your team's folder), need no teammate coordination, and directly de-risk the
two most-watched demo surfaces (the git answer and the live feed).

## 10. How the project is progressing (and what to guard against)

The team did the hard, correct things in order: deep research → a binding plan → a real data layer → an MCP-native agent
core → and now an **end-to-end slice that found the one real blocker**. That last move is exactly the discipline that
wins hackathons: it replaced a fog of assumed risk with a single, nameable gate. The engineering quality is high and the
doc system (OVERVIEW/DESIGN/LOG) is honest about the gaps — which is rarer and more valuable than the code itself.

The remaining risk is **integration and narrative honesty, not capability.** The parts are built; the wires between them
(delegate seam, real Kafka, Path-C retrieval) and the *truth of a few claims* (pgvector, the 125 ms path, the container)
are what's left. None is more than hours of work.

**Guard against:** (1) polishing pillars in isolation (more avatar realism, more KG routes) instead of flipping the
toggle and wiring the one seam; (2) letting the pitch describe pgvector/hybrid retrieval/one-container as *done* when the
code says otherwise — a single judge question turns an aspiration into a credibility hit; (3) leaving #0 and #4 "pending"
a person who hasn't been asked. The marginal *wire* and the marginal *honest sentence* are each worth far more right now
than the marginal feature.
